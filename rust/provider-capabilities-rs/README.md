## Source metadata and replay

The embedded JSON contains the original capability tables, ordered globs,
service kind flags, CommandCode text-only IDs, and vision regexes. Refresh it
from the checked-out source without loading router credentials:

~~~sh
node --no-warnings rust/provider-capabilities-rs/export-metadata.mjs \
  > rust/provider-capabilities-rs/src/provider-capabilities.json
rust-anything record rust/provider-capabilities-rs \
  --module "$PWD/rust/provider-capabilities-rs/reference.mjs" \
  --inputs rust/provider-capabilities-rs/inputs.jsonl
rust-anything gate rust/provider-capabilities-rs
~~~

The reference calls the original capabilities module and injects fixture data
through its catalog and combo callback interfaces. The Rust API exposes
model_capabilities, service_kind_capabilities, and combo_capabilities
through port. Pass the parsed model-catalog.json, if present, for live
overrides. For combos, pass a Rust function that can return capabilities for
an individual seat. The crate does not fetch or refresh the catalog.
