# 迁移决策

## ADR-001 迁移范围与基线

状态：已确定（2026-11-19）。

以 decolua/9router 的 `1855aa44473e88feac9d3f131b9c0c5fc9706b68` 为参考。迁移网关、管理台、CLI 和 Provider 定义。之前在本地 fork 额外实现的 Gemini Interactions 和 Antigravity Agent 不纳入。最终运行不依赖 Node.js。

## ADR-002 兼容目标

状态：迁移默认（2026-11-19）。

保留原版对外 API 的方法、路径、状态码、响应、鉴权、流式事件和错误约定。后续按同样方式录制 CLI 的参数、退出码和行为。管理台保留现有功能和操作流程，样式和静态资源可以复用。先在本机 Linux 复现，其他上游支持的平台分别核验。

## ADR-003 回放与过渡入口

状态：迁移默认（2026-11-19）。

以 `rust-anything app record` 保存上游运行结果，通过 `app replay` 比较 Rust 入口。跨进程回退保留到各单元迁完。过渡入口只监听回环地址，用空数据库和独立网络命名空间采集与回放。流式响应边读边转发。

## ADR-004 持久化与真实上游

状态：迁移默认（2026-11-19）。

保留 SQLite 数据格式，由旧库的脱敏副本验证读写、升级和恢复。账号凭据、API key 和真实用户数据不进入录制文件。先在本地模拟上游录制成功、错误、限流和 SSE，再单独验证真实 Provider。
